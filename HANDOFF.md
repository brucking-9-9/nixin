## Done and verified

Files (all new unless noted):

- `src/nixin/writer/nixtext.py` — the writer's own Nix tokenizer + structural scanner.
  It lexes everything (`"…${…}…"`, `''…''` with its escapes, paths incl. `./a/${x}.nix`,
  `<…>`, `~/…`, URIs, `1/2` as a path, block and line comments) with character offsets,
  matches brackets and `let`/`in`, and walks attrset bindings through function headers,
  `let … in`, `with x;`, `assert`, `//`, `++`, `lib.mkIf`/`optionals`/`optionalAttrs`
  (marked conditional), `lib.mkMerge [ … ]`, and the priority wrappers (`mkForce`,
  `mkDefault`, `mkOverride n`, `mkBefore`/`mkAfter`/`mkOrder`, recorded). Full-form modules
  (top-level `options`/`config`) have `config.` stripped, as the module system does. It
  exists because truth's `scan.py` is explicitly line-heuristic ("never used to edit a
  file blindly"). Robustness: lexes and walks all 79 `.nix` files of the config and 4240
  files of nixpkgs (`nixos/modules`, `lib`, `pkgs/top-level`) + home-manager with zero
  failures (27 s).
- `src/nixin/writer/workspace.py` — `Workspace.open()` (the `not-a-workspace` checks:
  `/etc/nixos` by path or by realpath, and `os.access(W_OK)`), hosts and their `modules`
  from flake.nix (`nixosConfigurations.<host> = ….nixosSystem { modules = [ … ]; }`,
  quoted names, inline attrset modules), the `imports` closure (path literals and
  `(import ./x)`, dirs → `default.nix`), HM users (`home-manager.users.<u> = import ./x |
  ./x | { … }`), `package_decls()` (every element of every list literal assigned to
  `environment.systemPackages`/`home.packages`), `option_decls()` (exact bindings,
  opaque ancestors, descendants). Generated files (first line = the header) are never
  treated as hand-written.
- `src/nixin/writer/edits.py` — offset edits, line-aware removal (an element or binding
  that owns its line(s), trailing comment included, takes the whole line; comments above
  stay; a removal between two blank lines takes one of them too; a shared line loses just
  the span), `imports` insertion (new line before a `]` that starts its own line; any
  other list is rewritten one item per line and its original text kept in
  `state.json` `imports` so removal restores it byte for byte), unified diffs.
- `src/nixin/writer/state.py` — `installer/state.json` (`version`, `nixos.<host>`,
  `home.<user>`, each `{packages, options}`; `imports`), `render()` (header comment,
  `{ config, lib, pkgs, ... }:`, `pkgs.<attr>` list, options as dotted attrpaths with the
  raw value), `Tools` (`nix-instantiate --parse -`, `nixfmt -`).
- `src/nixin/writer/__init__.py` — `register()` and the verbs `add`, `rm`, `set`, `unset`
  with `--config --home --host --json --dry-run --no-eval` (+ `--where FILE:LINE`,
  repeatable, for `rm`/`set`/`unset`). Everything is computed in an in-memory transaction;
  any error writes nothing. After a write: `git add --intent-to-add` for created files
  (flakes only see files git knows; verified necessary with a scratch repo), `git rm
  --cached` for deleted never-committed ones, `nix-instantiate --parse` on each touched
  file, one eval (see below). Pre-check for `add`: one small eval that the attribute exists
  in the host's `pkgs` (`unknown-package`).
- `cli.py`: one import + `writer.register(sub)`. `tests/test_cli.py`: writer verbs join
  truth's in the `config-not-found` branch. `package.nix`: `nixfmt` in
  `nativeCheckInputs` (the real-nixfmt render test runs in the sandbox). README: "Writer
  output" section + Status line.

## Half-done / limits (known, not bugs)

- Text-only module discovery: modules imported through an expression (`map`,
  `builtins.readDir`, `lib.filesystem.listFilesRecursive`, `inputs.x.nixosModules.y` that
  live in the repo) are invisible, and so are `home-manager.sharedModules`. A package
  declared there gives `not-found` (with hints) instead of an edit; nothing is guessed.
  Hosts built by a helper function or flake-parts fall back to `hosts/<h>/default.nix` /
  `configuration.nix` with a warning (`unknown-host` only if `nix eval` agrees).
- `already-declared` on `add` counts conditional lists (`lib.optionals false [ sl ]`) too;
  `rm` of such an element warns that it was conditional.
- `set` on a sub-path of an attrset some module defines (`services.openssh.settings` in
  `ssh.nix`) goes to the generated file (attrsOf merging). That is correct for submodules
  and attrsOf; an option whose type does not merge would give a conflict that only the
  eval check (option value) reports.
- `set` of an option a nixpkgs module defines at normal priority (not a default) adds a
  conflicting definition; the eval check shows nix's "conflicting definition values"
  error as a warning. There is no automatic `lib.mkForce`.
- `rm`/`unset` without `--home` only look at the NixOS scope (and vice versa); the other
  scope is mentioned in the `not-found` hints.
- Removing the last element of a hand-written list leaves `[ ]`; removing the last binding
  leaves `{ }`. Valid, not pretty.
- `nix fmt -- --check` (the README's command) does not work in this flake: the formatter
  is bare `nixfmt`, and with no paths `nix fmt` gives it stdin ("unexpected end of
  input"). Use `nixfmt --check $(git ls-files '*.nix')`. Belongs to the skeleton
  (`formatter = pkgs.nixfmt-tree` would fix it); not changed here.
- Human output prints warnings before the summary line (so: diff, warnings, one summary
  line).

## Open questions

- Should `eval-failed` after a write keep `ok: true` (today: the text change happened,
  `checks.eval.ok == false` + a warning) or be `ok: false` with the changes attached?
- `--host` default is this machine's hostname (cli.py); `--home` users are looked up on
  that host, so `add --home brucking` on mbp13 needs `--host 19BK` (the error says so).
- One generated HM file per user (`installer/<user>-home.nix`): if two hosts import the
  same `home/home.nix`, the user's additions apply on both. Per-host HM files would need
  `installer/<user>@<host>-home.nix` and a host-specific import site.

## How to test

```
nix develop -c pytest                                   # 55 offline tests, fixtures only
NIXIN_LIVE=1 NIXIN_CONFIG=~/nixin-test-config nix develop -c pytest -k live
NIXIN_LIVE_HOST=mbp13 …                                 # the live add/rm on another host
nix develop -c ruff check src tests && nix develop -c ruff format --check src tests
nixfmt --check $(git ls-files '*.nix')
nix build                                               # pytest in the sandbox
```

By hand, on a throwaway clone (never `~/nixos`): `git clone -q ~/nixos ~/nixin-test-config`,
then e.g. `nix run . -- --host 19BK add --home brucking cowsay --config ~/nixin-test-config`
(`--dry-run` to only see the diff, `--json` for the contract), and `git -C
~/nixin-test-config status` to see that `rm` puts everything back.
